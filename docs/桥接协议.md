# 桥接协议与坐标

网页端口 `18125`，MC 端口 `18126`。两者只绑定 `127.0.0.1`；MC CORS 允许来源为 `http://127.0.0.1:18125`。这是本机开发接口，未提供远程身份认证，不应原样开放到公网。

## 坐标

以 `ExampleModClient` 常量为准：`UNIT=32`、`OX=2600`、`OZ=8`。

```text
MC x = (Flash x + 2600) / 32
MC z = Flash y / 32 + 8
Flash x = MC x * 32 - 2600
Flash y = (MC z - 8) * 32
Flash height = (MC y - 80) * 32
```

游戏视口为 960×540；原游戏碰撞和关卡边界另有针对宽屏的适配，不能只改 CSS 缩放。世界坐标与屏幕坐标还需加上原游戏镜头偏移，并与 `motion.js` 的采样帧对齐。

## Flash ↔ 网页

| 回调 | 含义 |
|---|---|
| `mcStart` | 加载完成后进入玩法帧，由根时间轴补丁注册 |
| `mcState` | 导出原场景、玩家代理、敌人、物体、碰撞及事件 |
| `mcPosition` | 更新原游戏玩家代理位置、高度和朝向 |
| `mcView` | 获取当前镜头及帧序 |
| `mcApply` | 应用 MC 返回的状态与伤害反馈 |
| `mcReset` | 重开原游戏玩法 |
| `mcBossStage` / `mcNextStage` | 开发演示用 Boss / 检查点入口 |

## 网页 ↔ MC

| 路由 | 用途 |
|---|---|
| `POST /state` | 提交 `game: dadnme` 和 `scene` 等 Flash 状态，同时读取 MC 状态 |
| `GET /state` | 观察 MC 状态；`ready:false` 是尚未建立玩法连接，不等同于进程未启动 |
| `POST /action` | 键盘、鼠标、物品和界面操作；按场景路由，执行进入队列 |
| `POST /reset` | 重开时清理当前桥接场景 |
| `/sprite` | 原生玩家透明 PNG |
| `/scene` | 方块、原生实体等场景图层；帧号用于匹配镜头 |
| `/frame` / `/hud` | 原生界面与 HUD |
| `/audio/…` | 原生音频事件/资源，细节见 `AudioHttp.java` |

网页约每 50 ms 同步一次。PNG 帧号与 MC 服务端 tick 不等同；动作进入服务端 tick 处理，渲染在客户端进行。HTTP 线程不直接决定世界状态。

接口未提供稳定的公开 SDK 承诺。实际 JSON 字段以 `brawler.as`、`web/index.html` 与 `ExampleModClient.java` 为准；此文档说明现有实现，未发明另一套消息格式。
